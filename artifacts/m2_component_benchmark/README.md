This directory preserves a one-off M2 component benchmark on audited primary traces at reference scale. It used physical GPU 1, the exact frozen Qwen output head and token features, and a zero dense adapter. The running M2 process on GPU 0 and production source were unchanged; no optimizer updates occurred.

- [report.json](report.json), labelled `reference`, contains measured synchronized timings, numerical parity checks, profiler counts, configuration, seeds, source hashes and audited trace provenance.
- [analysis.json](analysis.json) records `reference`-scale shard-read amortization and restart break-even arithmetic with `result_kind=arithmetic_estimate`. Full-fit runtime measurement is `not_run`.
- [executed_source.txt](executed_source.txt) is the exact executed script, archived unchanged as a source snapshot. Its SHA256 is `29cb9d08d57df4bba79214da3d58af90055617cd464a220f65ec1a3148094397`, matching `benchmark_script_sha256` in the report. It contains fixed paths and a GPU UUID; it is not a reusable pipeline CLI with `--scale` or config support. Reproduction requires the recorded environment, source versions, audited shards and frozen artifacts. [benchmark.log](benchmark.log) and the `*.trace.json` files retain the execution output and instrumented profiles.

The decision was to preserve the running M2 fit. Sampled arithmetic suggested 12.25–14.56 minutes of gross savings, but 10.09 minutes of uncheckpointed work had already elapsed at the recorded decision point. Implementation, validation and restart costs could consume the remaining margin. The candidate was not integrated and M2 was not restarted.

Coverage is three batches of eight blocks each, all with 120 logical slots; only two blocks contain live-full diagnostics. This does not measure trained or sparse adapters, backward passes, optimizers, checkpointing or statistics finalization. Shard reads were sampled once per source and amortized. Profiler timings include instrumentation overhead; reported performance comparisons use separate synchronized measurements. Deferred reductions preserved reported values bitwise; vectorized reductions introduced small documented FP32 rounding differences. No adapter-quality improvement is claimed.
